01 / why this edition

The pieces existed. Now their connections are explicit.

The research already identified shared memory, inspectable customer knowledge and reusable procedures. The blueprint carried many foundations forward, but scattered them across layers without a complete maintenance lifecycle or a research-to-code trace. This edition closes that specification gap. It does not claim a newly invented memory architecture, an implemented feature, or another Claude review.

Keep the operating architecture

Evidence → interpretation → admitted state → authorized action → verified outcome. The new knowledge contract complements this flow; it does not replace the record store or weaken the 1.4 semantics.

Make understanding a maintained capability

Connect setup, cross-episode knowledge, targeted clarification, device continuity, scoped learning and change explanations to named responsibilities and tests. Research findings are design inputs, not verified vendor internals or proof of our implementation.

1.5 consolidates maintained business understanding, product behaviour and traceability. It retains the 1.3 S0–S4 sequence, 1.4 acceptance semantics and unchanged 1.1 controls. Its S0 handoff supersedes earlier handoffs. Earlier editions are preserved; 1.2 is historical evidence, not a current code audit.

04 / the missing explicit contract

Maintain understanding without creating another truth.

The reusable unit is an evidence-backed business brief, not an unrestricted chat summary. Begin with one supplier. Use the same principles for a matter when that workflow is ready.

Accepted facts

Current authoritative records and their versions; exact critical values are read from the shared output.

Tentative meaning

Candidate links, uncertain patterns and unresolved questions; useful for investigation, not authority.

Approved ways of working

Scoped preferences, operating rules and procedures with owners, applicability and effective versions.

Narrative synthesis

Readable cross-episode history with original source dependencies; never independent corroboration.

KB01

Nominate

Create a brief only for an active workflow, repeated question or useful entity; retain an explicit reason. Do not summarize every message into every entity.

Persist / reference
Entity ID, business/matter scope, audience class, intended use, source references and creation reason.
Prove
An unrelated new supplier message does not rewrite every outlet brief.
KB02

Compile

Synthesize across eligible episodes. Label accepted fact, tentative interpretation, scoped preference, approved procedure and narrative separately. Critical quantities/statuses come from the shared version-bound result.

Persist / reference
Brief ID/version, claim or section dependencies, source spans/timestamps, record revisions, model/extractor version, coverage and unresolved questions.
Prove
Two repeated summaries of one complaint still represent one underlying observation.
KB03

Invalidate

A matching correction, backfill, processed attachment, extractor/policy change or grant change marks affected claims for revalidation. Use reverse dependencies plus scoped selectors for absence claims. A source timestamp alone is insufficient.

Persist / reference
Changed dependency, invalidation reason, affected claims/views, queued refresh and historical version.
Prove
A late credit note invalidates the matching no-credit conclusion; unrelated supplier briefs remain valid.
KB04

Refresh

Revalidate operationally critical values before reliance. Batch or lazily refresh descriptive synthesis with explicit freshness. Under budget pressure, retain originals and show pending coverage; never silently present old synthesis as current.

Persist / reference
Last successful refresh, evaluated source/processing revisions, refresh mode, pending/failed status, budget and retry state.
Prove
Correction arrives during refresh: version check prevents publishing a superseded brief as current.
KB05

Use & inspect

Retrieve only currently allowed content. Use fresh records for current quantities, dates and state; briefs explain history and select further evidence. Show what the assistant knows, why, uncertainty and what changed. A user can flag irrelevant context without deleting evidence.

Persist / reference
Requester, purpose, destination audience, policy revision, selected brief/record versions and source citations.
Prove
Revoke an accountant source: its content cannot leak through the cached supplier brief or its title.
KB06

Retire & evaluate

Supersede historical briefs, apply retention/deletion to derivatives and indexes, and promote useful knowledge/procedures only at the appropriate scope. Preserve correction history under policy; generated answers never become fresh independent evidence.

Persist / reference
Supersession, retention policy, approved scope/owner, evaluation version and rollback reference.
Prove
New related question improves with corrected history; one-off exception does not become a standing rule.
Minimal storage decision

Use the existing record/evidence stores where verified. Store brief metadata and versions plus dependencies; render readable pages or Markdown exports. A reverse-dependency index supports invalidation. Access scope travels with derived content. Exact tables and queues depend on the S0 source audit; do not create a competing ledger or require a graph database.

05 / the machinery beneath the belt

The harness serves the workflow.

The harness coordinates model calls and tools. Business records, policy enforcement and durable state remain explicit services or modules outside model discretion. These responsibilities can begin inside the existing application; this diagram does not mandate separate deployments.

Trace and evaluatorAll stages / BP12Capture redacted provenance and outcomes; run replay cases without mistaking a trace for proof of correctness.

Data & identity

PostgreSQL for transactional records and references; object storage for media; indexes and briefs are derived. Current grants apply to source and derivative reads.

Execution & recovery

A small existing app/worker path first. Durable work records, leases, reconciliation and restore checks. Choose another runtime only for a demonstrated gap.

Trust & observation

Tenant isolation, secrets, untrusted input, revisions, audit provenance, connector health, processing completeness and retention cross every stage.

Experience & cost

Quiet normal work, targeted questions, visible pending states and per-tenant budgets. Measure completed useful work and human effort, not only tokens or tool calls.

Where modalities fit

Voice/photos enter at BP03 and are interpreted at BP04; voice readbacks use BP11’s shared output. Browser actions belong at BP09, with observation evidence returning through BP03. Video becomes bounded observations with timestamps and uncertainty. Native desktop awareness, broad video capture and autonomous agent-to-agent exchange stay deferred until a measured workflow justifies them.

08 / efficiency and scale

Measure the maintenance—not just the answer.

A useful brief may reduce repeated reconstruction. High update volume or rare reuse can make it more expensive. No performance percentage is claimed.

For a period, maintained knowledge is cheaper only when Q × (baseline per-query cost − brief-assisted per-query cost) exceeds initial compilation plus all update/maintenance costs. This is an analytical condition, not a measured result; quality, privacy and human effort must also pass.
  • A: raw retrieval plus exact current-record lookup
  • B: summary plus exact lookup (existing 1.4 baseline)
  • C: governed workflow without maintained cross-episode briefs
  • D: the same governed workflow plus one maintained supplier brief
Fairness
Hold model/version, eligible evidence timeline, permission boundaries, tools and task instructions comparable. Specify how B summarizes and refreshes so D is not compared with an artificially weak baseline. Report budgets and any unmatched capabilities.
Cases
One development episode family; reserve fresh supplier/outlet/wording families for evaluation. Include repeated questions, rare questions, high update rates, near-duplicates, late assets, ambiguous links, revocation and a correction during brief refresh.
Scorecards
Understanding: identity, quantities, relationships, correction handling, uncertainty, source support and useful cross-episode synthesis. Workflow: false alerts, repeated/necessary clarifications, owner interventions, incorrect closure and unresolved work. Track format and effect validity separately.
Cost
Total = intake + extraction + indexing + initial compilation + refresh/invalidation + retrieval + answering + retries + human review. Report storage/media/index growth, queue age, p50/p95 latency, correction-to-safe-read delay and model/provider charges separately.
Decision
Keep the brief only if it improves useful answers or repeated-work effort at an acceptable measured maintenance cost without weakening correctness or access controls. Thresholds depend on pilot workload and must be agreed before evaluating protected cases. No claimed percentage improvement.
Complexity
With N stored objects, E dependency edges and B retained source bytes, base storage is O(B + N + E) before media/index/vector overhead. Invalidating D affected descendants through E_D relevant reverse edges is O(D + E_D); selector lookup for absence claims adds work. Broad rule changes can touch most objects. Retrieval depends on indexes, selectivity and permissions; no constant-time promise. Model compilation cost depends on input/output tokens and update fan-out.

This is a bounded evaluation addition. S0 inventories capabilities and prepares the comparison; it does not wait for a full benchmark. Do not delay already agreed ordinary-work, voice, reports or acknowledgement work to build an elaborate knowledge platform.

Task survives device change; closure satisfies its own evidence/authority predicate; correction reopens affected work.

Exit evidence

Document bounded reliance, real effort/adoption and costs. Expand knowledge coverage only on evidence. Native capture, camera monitoring, agent-to-agent network and broad platform replacement remain deferred.
